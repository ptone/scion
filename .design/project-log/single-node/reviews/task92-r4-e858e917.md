# `e858e917` — let isCloudRunSandboxEnvironment() dominate SkipRuntimeCheck — Review

## Executive Summary

Two-file delta (one predicate change, two new tests) that removes an incorrect guard
on a machine-fact check. The change is correct and well-tested. Risk level: **LOW**.

---

## The Four Checks

### 1. Is the negative direction safe?

**Confirmed safe.**

The predicate is an unchanged two-condition conjunction:

```go
func isCloudRunSandboxEnvironment() bool {
    return os.Getenv("CLOUD_RUN_INSTANCE") != "" && sandboxBinExists(defaultSandboxBin)
}
```

The case the brief names — **env set, seam false** (a Cloud Run *service*, not an
Instance) — evaluates to `true && false = false`. The `if` branch is not taken; the else
branch runs. The cloudrun-sandbox template is NOT seeded on a Cloud Run service. This was
true before the change (when the conjunction was also guarded by `SkipRuntimeCheck`) and
remains true after: removing the outer guard does not alter the conjunction itself.

The developer's negative test (`TestInitMachine_NonCloudRun_SkipRuntimeCheckFalse_SeedsWorkstationTemplate`)
covers env-unset + seam-false, not env-set + seam-false. This is a **coverage gap** — see
Nit #1 below — but the predicate logic is sound regardless.

### 2. The caller survey, and "normally"

Three callers exist at `e858e917`:

| Caller | `SkipRuntimeCheck` | Notes |
|---|---|---|
| `cmd/project.go:85` | `false` (default) | CLI `scion project init`. Workstation-only; never runs on Cloud Run. |
| `cmd/server_foreground.go:107` | `hostedMode` (= `true` on Cloud Run) | Server startup. Seeds settings **before** the HTTP listener starts. |
| `pkg/hub/system_handlers.go:514` | `false` (default) | Hub `/api/system/init` handler. Called via HTTP after server is running. |

**"Normally" is well-defended by code ordering, not by coincidence.**

`server_foreground.go` runs `InitGlobal` at step 4 (line 107), synchronously, before
the Hub HTTP server is initialized at step 11 (line 258). On first boot the directory
does not exist, so InitGlobal runs and seeds settings with `SkipRuntimeCheck: true`.
The HTTP listener starts later; by the time a client can hit `/api/system/init`, settings
already exist and `GetSettingsPath` returns non-empty, so InitMachine's seeding block is
skipped entirely.

**The edge case**: `server_foreground.go` (line 105) guards on `os.IsNotExist(globalDir)`,
not on the settings file. If the directory exists but `settings.yaml` is absent (manual
deletion, partial wipe, or a previous run that created `~/.scion/` but crashed before
writing settings), the server startup path skips seeding. The HTTP listener starts, a
client hits `/api/system/init`, and the Hub handler's InitMachine call is the first to
find `GetSettingsPath == ""`. Before this fix, that path called `DetectLocalRuntime()` on
a Cloud Run Instance — a hard error. After this fix, `isCloudRunSandboxEnvironment()`
returns true and the correct template is seeded.

**Verdict on "defence in depth"**: accurate for normal first-boot and restart flows. The
edge case (dir exists, settings missing) is reachable but requires abnormal prior state.
The commit message already acknowledges it: *"making this reachable if settings are absent
when that handler fires."* Characterization is fair.

### 3. Tests assert content, not absence of error

**Confirmed — the substitution is genuinely equivalent in strength.**

The positive test asserts:
- `active_profile` matches the cloudrun-sandbox template's value (`"default"`)
- Profile set matches (count + per-profile runtime)
- Runtime set matches (count + per-runtime presence)
- **Negative guards**: workstation-only profiles (`local`, `remote`) must be absent;
  workstation-only runtimes (`docker`, `podman`, `kubernetes`) must be absent

If the workstation template were seeded, at least six independent assertions fire:
`active_profile` is `"local"` not `"default"`, profile count is 2 not 1, `"default"`
profile is missing, runtime count is 4 not 1, `"cloudrun-sandbox"` runtime is missing,
and the negative guards catch `local`/`remote`/`docker`/`podman`/`kubernetes`. This is
strictly stronger than a byte comparison for the purpose of distinguishing the two
templates, and correctly handles the `ensureBrokerID()` mutation (which adds broker_id
and strips comments via YAML round-trip).

### 4. The mutation

**Re-run confirmed.** Inverting `if isCloudRunSandboxEnvironment()` to
`if false && isCloudRunSandboxEnvironment()` causes the test to go red on **content
assertions**, not on an error string:

```
init_test.go:1251: active_profile = "local", want "default"
init_test.go:1258: profile count: got 2 ([local remote]), want 1 ([default])
init_test.go:1265: profile "default" missing from seeded settings
init_test.go:1278: runtime count: got 4 ([container docker kubernetes podman]), want 1 ([cloudrun-sandbox])
init_test.go:1284: runtime "cloudrun-sandbox" missing from seeded settings
init_test.go:1291: profile "local" is present — Cloud Run sandbox must not have workstation profiles
init_test.go:1291: profile "remote" is present — Cloud Run sandbox must not have workstation profiles
init_test.go:1296: runtime "docker" is present — Cloud Run sandbox must not have workstation runtimes
init_test.go:1296: runtime "podman" is present — Cloud Run sandbox must not have workstation runtimes
init_test.go:1296: runtime "kubernetes" is present — Cloud Run sandbox must not have workstation runtimes
```

Every assertion fires on the wrong template being seeded, not on an error from
`DetectLocalRuntime()` (which was mocked to succeed with `"docker"` precisely to force
this outcome). The mutation test is well-designed.

## Nit / Optional

### Nit #1 — Negative test covers env-unset but not env-set/seam-false

`TestInitMachine_NonCloudRun_SkipRuntimeCheckFalse_SeedsWorkstationTemplate` sets
`CLOUD_RUN_INSTANCE=""` and `sandboxBinExists → false`. This proves the workstation
path is taken when neither condition is met. It does NOT cover the Cloud Run *service*
case (env set, seam false) — the exact case the brief called out.

The predicate logic is safe regardless (checked above), and the test catches the
important direction (wrong template on a workstation). But a third test with
`CLOUD_RUN_INSTANCE="some-service"` + `sandboxBinExists → false` would nail down the
conjunction's second leg directly.

**Not blocking.** The predicate is a two-line conjunction that is trivially auditable.

### Nit #2 — Dead code: `truncate` helper

The `truncate(s string, n int) string` function (init_test.go:1363) is defined but
never called. Go does not flag unused functions, so it compiles fine, but it is dead
code introduced in this commit.

**Suggested fix:** Delete it, or use it where the test constructs error messages with
potentially long YAML content.

## Positive Feedback

The test design for the positive case is notably good. Mocking `DetectLocalRuntime` to
succeed with `"docker"` (rather than letting it fail) was a deliberate choice that makes
the mutation test catch the wrong-template bug via content assertions rather than an error
string. This is harder to write and more valuable — a test that fails on an error string
would pass if someone later made `DetectLocalRuntime` succeed on Cloud Run, silently
seeding the wrong template.

The inline comment added to init.go (lines 589-593) is precise: it names FACT vs.
PREFERENCE and states the invariant. It earns its lines.

## Test Coverage

The two new tests cover:
- The exact scenario that motivated the fix (Cloud Run Instance, `SkipRuntimeCheck: false`)
- The negative direction (non-Cloud-Run, `SkipRuntimeCheck: false` → workstation defaults)

Gap: env-set + seam-false (Cloud Run service) is not tested (Nit #1).

## Backward Compatibility

No wire-format changes. No removed fields. The change widens when the cloudrun-sandbox
template is seeded (callers that previously got an error now get a correct result), which
is the intent.
